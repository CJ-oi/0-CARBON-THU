技术说明

系统由公开来源采集、事件归并、园区实体映射、坐标审核、核算与项目组合、自动报告、邮件发送接口、质量门禁和 GitHub Pages 发布组成。

运行结构

公开来源、园区名录与项目参数
        ↓
相关性筛选、标题规范化、事件归并、来源健康
        ↓
园区实体映射、坐标审核、证据分层
        ↓
数据准备、现状画像、指标差距、措施建议、项目组合
        ↓
界面截图、日报、周报、可行性报告与 PDF
        ↓
测试、质量门禁和 GitHub Pages 发布

地图与坐标

在线浏览采用 Leaflet + OpenStreetMap，园区点位直接按纬度和经度落图；全国、国家级、广东和全球视图只改变筛选范围。网络不可用或生成报告截图时，系统使用同坐标系简化矢量备用图。坐标表记录经纬度、精度、来源、复核状态和复核日期。点位仅表示近似中心，法定边界应另行取得批复图或 GIS 数据。

公开信息处理

采集结果先计算相关性和质量分，低相关记录不进入公开页面；标题、文号、规范 URL 和正文指纹共同用于事件归并。日报和周报按园区建设、技术设施、项目投融资、政策标准和数据评估进行平衡抽样，不把同一事件重复列示。

减排建议

建议由指标差距与措施库规则匹配形成，输出措施层级、对应差距、前置数据、计算方法、经济性字段、主要约束和责任主体。缺少项目参数时只输出指南，不生成确定减排量或收益。

项目组合

项目以投资、年度减排、年度收益、运维、寿命、实施年份、证据等级、前置关系和互斥关系为输入。若存在满足目标的组合，选择净现值成本较低者；否则给出预算内最大减排组合和剩余缺口。组合形成后计算保守、基准和改善三种透明敏感性情景。只要入选项目含演示参数，结论明确标记为演示场景。

自动报告

构建流程使用无头浏览器截取首页、地图和五问工作台，并嵌入日报、周报和可行性报告；随后输出 HTML、Markdown、JSON 和 PDF。截图和报告随每次合格构建同步更新。

邮件发送

GitHub Pages 不保存邮件密钥。可选 Cloudflare Worker 对来源、邮箱、授权和报告类型进行校验，从本站固定路径读取 PDF，通过 Resend 发送。未配置时网页使用本机邮件客户端作为可用退路。

质量门禁

  • Python 单元与集成测试；
  • JavaScript 语法、页面自检和 Playwright 浏览器功能验收；
  • 园区坐标范围与国内点位检查；
  • 页面内部链接、按钮和报告文件检查；
  • PDF 生成和文件大小检查；
  • 任何门禁失败时停止部署，保留上一版成功网站。

安全边界

采集器只访问正常公开页面，不绕过登录、验证码、付费墙或限流。公开仓库不保存企业敏感台账、合同价格、个人信息和密钥。
