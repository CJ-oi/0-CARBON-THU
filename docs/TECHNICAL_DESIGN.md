# 技术设计说明


## 9. 自动发布与质量门禁

GitHub Actions 依次执行：

1. 更新公开信息；
2. 构建矢量地图和坐标审核表；
3. 运行测试；
4. 构建网站和报告；
5. 截图与 PDF 渲染；
6. 页面、链接、脚本和报告检查；
7. 提交增量数据；
8. 发布 GitHub Pages。

任何门禁失败时停止部署，上一版成功网站继续保留。

## 在线地图与坐标一致性

网页在线模式采用 Leaflet 的 EPSG:3857 坐标参考系统，并将园区表中的纬度、经度直接交给地图引擎定位；土地底图和点位不再分别进行屏幕坐标换算。全国、广东和全球视图只改变可视范围和筛选条件，不改变点位坐标。网络不可用或生成报告截图时，系统使用同一套经纬度与墨卡托换算生成简化矢量底图。

`data/coordinate_audit.csv` 对每个园区记录：点位精度、范围检查、坐标来源、复核日期和边界声明。公开点位用于导航，不作为园区四至边界。

## 可行性分析的敏感性检查

项目组合确定后，系统在同一项目集合上计算保守、基准和改善三种透明情景。情景只对投资、年度节省、运维和年度减排进行预先写明的比例变化，用于判断结论是否过度依赖单一参数。该结果是前期稳健性检查，不是概率预测，也不替代工程可研。
