# 技术设计说明

## 1. 总体结构

```text
公开来源、园区名录和项目参数
        ↓
相关性筛选、标题规范化、事件归并、来源健康
        ↓
园区实体映射、坐标审核、证据分层
        ↓
数据准备、现状画像、指标差距、措施建议、项目组合
        ↓
界面截图、日报、周报、可行性报告与 PDF
        ↓
测试、质量门禁和 GitHub Pages 发布
```

## 2. 数据治理

园区使用 `park_id` 作为稳定主键，标准名称、别名、省份、城市、地图点位和公开来源均映射到该主键。公开记录分为：

- 名录事实；
- 公开事实；
- 数值候选；
- 正式指标。

只有对象、空间边界、统计年度、单位、因子和原始材料均通过核验后，数据才可进入正式核算。

## 3. 动态采集与事件归并

采集器按来源配置读取正常公开网页，不绕过登录、验证码、付费墙或限流。处理链包括：

1. 来源健康检查；
2. 规范 URL；
3. 标题清洗和文号提取；
4. 零碳园区相关性评分；
5. 来源层级和完整度评分；
6. 标题与内容近似归并；
7. 主记录和补充来源保留；
8. 分类结构平衡；
9. 报告和网页重建。

## 4. 地图

在线浏览优先采用 Leaflet + OpenStreetMap。园区表中的纬度、经度直接交给地图引擎定位，全国、国家级、广东和全球案例只改变筛选范围，不改变点位坐标。若地图脚本或瓦片网络不可用，网页自动显示简化矢量备用图；备用图与点位使用同一套墨卡托换算。经纬度表记录：

- 坐标值；
- 精度；
- 复核状态；
- 来源；
- 复核日期。

点位仅表示近似中心。法定边界应使用园区批复图、GIS 文件或经核验的四至坐标替换。

## 5. 指标差距与减排建议

指标差距模块在确认园区边界和自然年后运行。减排建议模块把未达指标与措施库中的关键词、适用对象和前置条件匹配，输出：

- 无悔型、条件型或战略型；
- 对应差距；
- 前置数据；
- 减排计算逻辑；
- 经济性字段；
- 主要约束；
- 责任主体。

缺少项目参数时不生成确定减排量和收益。

## 6. 项目组合

输入包括投资、年度减排、年度节省、运维、寿命、实施年份、证据等级、前置关系和互斥关系。组合算法在预算和减排目标约束下选择项目：

- 有满足目标的组合时，优先选择净现值成本较低的组合；
- 没有满足目标的组合时，给出预算内最大减排组合及剩余缺口。

## 7. 自动报告与截图

无头浏览器在每次合格构建时自动截取：

- 首页和数据快照；
- 园区地图与资料卡；
- 五问工作台与自动建议。

截图嵌入日报、周报和可行性报告，随后生成 HTML、Markdown、JSON 和 PDF。

## 8. 邮件发送

GitHub Pages 不保存密钥。可选 Cloudflare Worker 校验来源、邮箱、授权和报告类型，从网站固定路径读取 PDF，再通过 Resend 发送。网页即时可行性摘要会经过长度限制和 HTML 转义后写入邮件正文。

## 9. 自动发布与质量门禁

GitHub Actions 依次执行：

1. 更新公开信息；
2. 构建矢量地图和坐标审核表；
3. 运行测试；
4. 构建网站和报告；
5. 截图与 PDF 渲染；
6. 页面、链接、脚本和报告检查；
7. 提交增量数据；
8. 发布 GitHub Pages。

任何门禁失败时停止部署，上一版成功网站继续保留。

## 在线地图与坐标一致性

网页在线模式采用 Leaflet 的 EPSG:3857 坐标参考系统，并将园区表中的纬度、经度直接交给地图引擎定位；土地底图和点位不再分别进行屏幕坐标换算。全国、广东和全球视图只改变可视范围和筛选条件，不改变点位坐标。网络不可用或生成报告截图时，系统使用同一套经纬度与墨卡托换算生成简化矢量底图。

`data/coordinate_audit.csv` 对每个园区记录：点位精度、范围检查、坐标来源、复核日期和边界声明。公开点位用于导航，不作为园区四至边界。

## 可行性分析的敏感性检查

项目组合确定后，系统在同一项目集合上计算保守、基准和改善三种透明情景。情景只对投资、年度节省、运维和年度减排进行预先写明的比例变化，用于判断结论是否过度依赖单一参数。该结果是前期稳健性检查，不是概率预测，也不替代工程可研。
