# 公开数据治理说明

## 1. 数据层级

平台将数据分为四层：

1. **名录事实**：园区名称、层级、地区、建设周期等公开名录信息；
2. **公开事实**：能够明确关联园区对象的公开描述或数字；
3. **候选事实**：对象、边界、年份或单位尚未完全核验的线索；
4. **正式指标**：同边界、同年度、同单位且有原始凭证的数据。

四层数据不能混用。候选事实可引导调研，但不能直接用于正式排名或达标判断。

## 2. 园区实体映射

`park_id` 是主键。园区标准名称、别名、省份、城市、名单层级、地图点位和来源均通过主键关联。无法自动匹配的记录应进入人工复核，不以模糊名称强行关联。

## 3. 证据字段

公开记录至少包含：

- 记录编号；
- 标题和短摘要；
- 发布日期；
- 发布主体；
- 原文 URL；
- 规范 URL；
- 主题和地区；
- 内容哈希；
- 首次和最近归档时间；
- 用途边界；
- 审核状态。

## 4. 版本与修订

同一规范 URL 内容发生变化时，保留首次归档时间、前一内容哈希和版本计数。公开数据修订通过 Issue 留痕，合并后由下一次构建重新生成网站和报告。

## 5. 数据质量规则

- 园区名称必须映射到唯一 `park_id`；
- 日期不得晚于采集日；
- 数值必须带单位；
- 绩效数据必须带空间边界和统计年度；
- 来源 URL 应为 HTTPS；
- 市级、企业级和园区级数据不得互相替代；
- 结构相似度不得写成绩效排名；
- 演示参数必须显式标注；
- 来源无法访问时记录失败，不以演示数据冒充实时结果。

## 6. 开放与敏感数据

公开仓库适合保存公开名录、政策链接、短摘要、规则、指南和脱敏场景。不应保存：

- 企业未公开能耗和排放台账；
- 个人信息；
- 合同价格和商业秘密；
- 未公开的 GIS 边界；
- 访问密钥和账号密码。

需要处理敏感数据时，应在私有环境运行同一计算模块，仅将经过审核的结果发布到公开网站。
